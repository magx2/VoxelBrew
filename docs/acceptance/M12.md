# M12 acceptance — release automation

This increment prepares release automation; it does not authorize or publish
the first product release. The source conventions were inspected at
electrotechnika `c3738f3` and Bigboy `b8eff5c`. See [release steps](../releases.md)
for the branch/version examples, platform scope and recovery procedure.

Validation includes release-script tests against temporary Git repositories,
Spotless and actionlint, full root checks on Windows and a separate Ubuntu WSL
checkout, the normal CI matrix and a non-publishing release rehearsal. Rehearsal
workers build the actual release-version commit and exercise extracted native
archives, including the CLI version and externally built plugin fixture.

Local evidence is retained under `.tools/release-*` and platform
`build/package-artifacts/archive` directories. Hosted Actions retain reports,
screenshots, candidate bundle, provenance and downloads for three days. The
committed workflow is reproducible; run-specific results and exact commit/run
links are reported at handoff rather than claiming tests passed before execution.

The Windows workstation previously lacked JavaFX SCENE3D; its full root check
is still attempted unchanged. A hosted Windows full check is required if that
graphics limitation persists. macOS qualification is explicitly CLI-only.
Publishing permissions/protected-branch policy, actual GitHub Release upload,
signing/notarization and physical printer use are not proven by a dry run.
