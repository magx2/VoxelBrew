## Automated feature evidence

- Unit tests verify immutable opaque payloads, value equality, transaction identity
  and parameter metadata/validation without native initialization.
- Real OCCT integration tests load the separately compiled provider from a path
  containing spaces, measure the analytic spacer, check the hole, edit height,
  undo/redo and split its named output. Native handle counts return to baseline.
- Missing-provider tests remove/reinstall the JAR. Failed/blocked diagnostics
  prevent geometry access; saving preserves exact bytes and IDs. Reinstalling
  rebuilds the same outputs. Future/corrupt payloads stay savable.
- Duplicate, incompatible, missing-class and failing providers are isolated.
  Invalid edits leave the prior session/file intact. Schemas 1 and 2 still reopen
  and edit correctly; newer schemas retain the existing read-only protection.
- Fresh-process CLI tests create/edit/reopen/export a spacer, preserve the prior
  export after a missing-provider failure, restore the provider, place the part,
  and slice it into 40 model layers with the real pinned PrusaSlicer backend.
- Controller tests verify background rebuilding, stale-geometry removal, missing
  plugin saving, reinstall recovery and undo after recovery. A rebuild invalidates
  completed/running slice jobs even when provider payload bytes are unchanged.
- The actual JavaFX Robot workflow creates a spacer with numeric fields, rejects
  invalid dimensions, cancels without an undo entry, edits 5→8 mm, undoes/redoes,
  saves/reopens with the plugin removed, saves the unavailable definition,
  reinstalls/rebuilds and exports 3MF. An installed CLI independently checks the
  saved part's hole. Screenshots are under `gui/build/ui-artifacts/custom-spacer.png`.
- Packaged CLI checks load/create/edit/inspect/export the custom feature with the
  bundled JVM and no Java on PATH. The 3MF reader verifies its separate body ID.
