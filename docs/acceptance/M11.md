# M11 — Bounded parallel computation

[Computation architecture and audit](../computation.md) describes the implemented
paths, CPU budget, cancellation guarantees and work deliberately kept serial.

## Correctness coverage

- `CpuWorkTest`: actual overlapping workers, a bounded peak count, every index
  executed once, nested work without deadlock, ordered map output, sequential
  fallback, invalid budgets, failure draining and interruption draining with
  interrupt-status preservation.
- `ParallelSketchTest`: exact equality with serial geometry, rank/degrees of
  freedom and conflict diagnostics for a sketch above the parallel threshold.
- `ParallelGeometryTest`: real OCCT batches match serial vertices, triangle
  indices and face mappings; original volumes remain unchanged, meshes remain
  closed and native handle counts return to baseline after success and failure.
- `ManufacturingTest`: repeated placements share one topology report and produce
  stable validation diagnostics across runs.
- `FootprintTest`: the batched projection matches independent per-triangle unions
  for holes, overlapping opposite-winding triangles, edge-on faces, separate
  regions, rotated placements and translations. A JVM stack sample identified
  repeated `Area.add`/`AreaOp.pruneEdges` calls as a print-preflight hotspot.
- Existing controller and Robot suites exercise stale-result rejection, failed
  rebuild geometry clearing, cancellation, history, printing, file operations,
  plugins and both palettes with the new computation paths.

## Reproduction and evidence

Windows 11 / Corretto 21.0.6 / 12 available processors, warmed median milliseconds:

| Workload | 1 worker | 4 workers | 8 workers | 1-to-8 speedup |
| --- | ---: | ---: | ---: | ---: |
| Mesh 12 bodies / 144 holes | 5303.748 | 1638.409 | 1237.606 | 4.29× |
| Preflight 12 instances | 328.785 | 139.028 | 107.490 | 3.06× |
| Solve 192 variables | 169.364 | 121.374 | 128.464 | 1.32× |

Meshing/preflight figures use the complete benchmark; solver figures use the
longer-warmed `-PcomputeScenario=sketch` run. Both compare the same algorithms at
different worker budgets. The 96-variable exploratory results varied with JVM
warm-up, so the final implementation keeps that smaller size serial. The default
cap of eight favors meshing/preflight; four remains a configurable choice.

Ubuntu WSL / Temurin 21 / 12 available processors, warmed median milliseconds:

| Workload | 1 worker | 4 workers | 8 workers | 1-to-8 speedup |
| --- | ---: | ---: | ---: | ---: |
| Mesh 12 bodies / 144 holes | 1287.942 | 373.039 | 278.810 | 4.62× |
| Preflight 12 instances | 334.730 | 133.958 | 105.740 | 3.17× |
| Solve 192 variables | 157.845 | 117.903 | 129.565 | 1.22× |

Ubuntu figures use the final complete benchmark. Runs were sequential, with no
competing build/test workload. Native compiler/platform differences make the
within-platform comparison meaningful; these numbers do not qualify overall
Windows-versus-Linux performance. The initial Windows profiling run was stopped
after its stack sample exposed repeated footprint unions; that incomplete run
is kept as `.tools/parallel-initial-stopped.log` and is not an acceptance run.

Run `gradlew.bat :engine:computeBenchmark -PcomputeThreads=1`, then repeat with
`4` and `8`. Ubuntu uses `./gradlew` in its separate filesystem checkout.
Performance results are workload-specific; no test asserts a wall-clock speedup.

Full Windows gate: `gradlew.bat check`. Hosted Windows uses
`gradlew.bat check -PvsGenerator="Visual Studio 17 2022"`.
Full Ubuntu gate:

```sh
xvfb-run -a -s "-screen 0 1600x1000x24" env LIBGL_ALWAYS_SOFTWARE=1 ./gradlew check
```

Preserved logs use `.tools/parallel-*.log`; platform reports, screenshots and
benchmark transcripts use `.tools/parallel-wsl-evidence`,
`.tools/parallel-local-windows` and `.tools/parallel-hosted-windows`.
The final revision, commands, measurements, counts and CI links are recorded in

hosted Windows qualification. macOS GUI remains deferred by the user; its
