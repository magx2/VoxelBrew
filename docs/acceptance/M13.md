# M13 acceptance — explicit application updates

The implementation adapts Bigboy's `SelfUpdate` at commit
`b8eff5cf67fb2f02e54dbd2783eebde00a4fff5c`. VoxelBrew updates complete native app
images through a shared engine service, CLI commands and a JavaFX dialog.
See [commands, platform scope and recovery](../updating.md).

Automated acceptance covers semantic version selection, mandatory checksums,
unsafe archives, executable permissions, failed replacement restoration, concurrent
update exclusion and failed downloads preserving the installation. Cleanup also
handles Windows read-only files; each packaged frontend prepares and cancels a
real update before exercising installation. The packaged
checks use an offline `gh` transport fixture with real bundled JVMs, actual
installation metadata and complete image swaps. A second fresh JVM holds the
running-instance lock until explicitly released. After replacement, the CLI
reopens the reference part through the real OCCT kernel; the GUI image's version
is checked through its launcher class.

The JavaFX Robot scenario checks both palettes, explicit versions, forced
reinstallation selection, cancelling an outstanding lookup, reopening without a
stale result, downloading/preparing an update and cancelling the unsaved-document
prompt. The small GUI release fixture deliberately stops before helper startup;
the separate packaged test qualifies helper startup and image replacement for
both frontends. These tests do not claim a complete GUI-driven live update.
