# M7 — constrained 2D sketches

The engine, CLI and JavaFX workbench share immutable sketch entities, geometric
constraints, driving dimensions and an SVD-based nonlinear solver. Exact OCCT
line/arc/circle/Bezier wires produce signed prisms and through cuts. Schema 4
retains existing identities and reads schema versions 1–3. See the
[user workflow](../sketch-constraints.md) for supported selections and limits.

## Automated cases

- `SketchSolverTest`: all geometric constraint families, dimensions, rank/DOF,
  fixed geometry, dragging, conflict detection, bad references and invalid values.
- `SketchControllerTest`: local undo/redo, failed drag recovery, transient drag
  cancellation, coalesced requests, stale result rejection and closed editors.
- `ConstrainedSketchTest`: real-kernel reference plate and hole, stable save/edit
  identities, history, signed semicircle prisms, exact Bezier area, through cuts,
  immutable source solids, invalid profile diagnostics and repair.
- `WorkflowTest`: fresh-process constrained plate conversion, dimensions, failed
  writes preserving bytes, fixed-point rejection, moving released geometry,
  3MF export, regular polygon and exact Bezier profiles.
- `WorkbenchUiTest.constrainedSketchDimensionsConflictsHistoryAndFilesUseRealControls`:
  actual Robot rectangle/circle drawing, dimensions and conflicts, local history,
  one-operation Finish, exact reference volume, save/reopen, independent CLI
  inspection, global history, cancellation, light and dark palettes.
- `WorkbenchUiTest.sketchPointDragsCurvatureAndRegularPolygonsUseRealControls`:
  actual point dragging/release/Escape, local history, arc/spline drawing,
  reference selection, G2 joining, exact profile extrusion, regular polygon,
  global history and palette screenshots.

Focused engine, CLI and controller tests passed on Windows. Both new Robot
workflows passed in the separate Ubuntu 24.04 WSL2 checkout with Java 21,
JavaFX 21.0.13 and Mesa/Xvfb. Initial render testing caught and fixed a canvas
layout/fit ordering issue before the full regression gates.

## Reproduction and evidence

Windows root gate: `gradlew.bat check`.

Ubuntu root gate (separate filesystem checkout, independent native build):

```sh
xvfb-run -a -s "-screen 0 1600x1000x24" env LIBGL_ALWAYS_SOFTWARE=1 ./gradlew check
```

Focused WSLg interactions:

```sh
LIBGL_ALWAYS_SOFTWARE=1 ./gradlew :gui:e2eTest \
  --tests '*constrainedSketchDimensionsConflictsHistoryAndFilesUseRealControls' \
  --tests '*sketchPointDragsCurvatureAndRegularPolygonsUseRealControls'
```

Per-module reports are `build/reports/tests/{test,integrationTest,e2eTest}`.
GUI screenshots and the saved CLI-inspected reference part are under
`gui/build/ui-artifacts`; named images include `sketch-constraints-light.png`,
`sketch-constraints-dark.png`, `sketch-spline-curvature.png` and
`sketch-regular-polygon.png`. Local logs are `.tools/sketch-*.log`; preserved
platform evidence uses `.tools/sketch-wsl-evidence` and
`.tools/sketch-hosted-windows`. Exact full-gate outcomes and hosted links are
reported with the final commit at handoff.

The local Windows session has a known unavailable JavaFX 3D device; this is
reported as a failed GUI prerequisite, not a skipped test or headless GUI pass.
The full Windows gate is also run through `full-check.yml` on `windows-2022`
against the pushed commit. Routine CI checks Ubuntu/Windows packaged apps and
macOS headless workflows. macOS GUI qualification remains explicitly deferred.
Hosted artifacts retain the requested three-day lifetime.
