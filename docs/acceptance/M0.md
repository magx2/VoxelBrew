## Reproduction

Windows PowerShell, repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\bootstrap-native.ps1
.\gradlew.bat :engine:nativeIntegrationTest
.\gradlew.bat :cli:run --args=native-demo
.\gradlew.bat check
```

Ubuntu, repository root:

```bash
bash scripts/bootstrap-native.sh
./gradlew :engine:nativeIntegrationTest
./gradlew :cli:run --args=native-demo
./gradlew check
```

The WSL test was invoked from Windows using
`wsl -d Ubuntu --exec bash -lc 'cd /tmp/voxelbrew-m0; ./gradlew check'`.
Every full check runs all three subprojects with no task exclusions. `gui` has
no sources yet; the CLI is a smoke demo, so both currently have no test classes.

## Failures investigated and resolved

1. Windows `gradle wrapper` initially could not validate the distribution URL
   inside the network-restricted shell. Generation was followed by a successful
   checksum-verified wrapper download. Committed URL validation is enabled.
2. Windows `:engine:buildNative` failed its CMake compiler probe with missing
   `kernel32.lib`, then `ucrtd.lib`. The host had MSVC but only SDK metadata.
   The bootstrap now acquires checksum-pinned Microsoft SDK headers, tools and
   x64 libraries locally; Gradle passes SDK and UCRT paths explicitly. A stale
   failed configure cache was removed when the SDK platform selection changed.
3. Ubuntu `./gradlew --no-daemon :engine:nativeIntegrationTest` initially failed
   `configureNative`: `Could NOT find JNI (missing: JAVA_INCLUDE_PATH
   JAVA_INCLUDE_PATH2 AWT)`. Gradle had selected an installed JRE for the native
   header lookup. The build now selects `compilerFor` (a full JDK), and CMake
   requests only JNI's JVM component. The corrected run passed.
4. Linux shared-library search paths are set to `$ORIGIN` for both OCCT and the
   bridge. No `LD_LIBRARY_PATH`, system OCCT installation or display is needed.
